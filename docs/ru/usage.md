# Использование

## Проверка

```sh
ha-meter-contracts check contract.json --json --lang ru
ha-meter-contracts check examples/minimal.yaml --at 2026-01-01T12:00:05Z --lang ru
```

Без `--at` используется текущее UTC-время. Для повторяемого результата задавайте время ISO 8601 с часовым поясом. Одинаковые вход, время и язык дают одинаковый JSON. Измерение считается свежим до границы `freshness_seconds` включительно; после неё оно устаревшее. Метки из будущего запрещены, неявного допуска на расхождение часов нет.

Коды завершения: **0** — нет ошибок и предупреждений; **1** — обнаружена проблема семантики или качества данных; **2** — неверный ввод, файл или аргументы. Информационное сообщение о неиспользованном в сумме псевдониме не приводит к ошибке. С `--json` и отчёт, и ошибка ввода печатаются в stdout. В текстовом режиме ошибка ввода выводится в stderr. Разрыв выходного канала возвращает 2.

Не скрывайте результат через `|| true` в CI. Для намеренно ошибочных примеров явно проверяйте код 1. Справка и версия возвращают 0. `import-ha` всегда выдаёт JSON-контракт, даже без `--json`.

## Библиотека Python

```python
from datetime import datetime, timezone
from ha_meter_contracts import audit, load_document, parse_contract

contract = parse_contract(load_document("examples/valid-three-meters.json"))
report = audit(contract, at=datetime(2026, 1, 1, 12, 0, 5, tzinfo=timezone.utc))
assert report["sums"][0]["value"] == 720
```

`parse_contract` создаёт неизменяемые dataclass-объекты. Ошибка `InputError` содержит `code`, `path`, `params`. Применяйте парсер ко всему недоверенному вводу. `audit` ожидает уже проверенный `Contract`, требует явного времени и не переводит сообщения. CLI добавляет локализованное поле `message`. Исходные объекты не изменяются, файлы не записываются.

## Сохранённый экспорт Home Assistant

```sh
ha-meter-contracts import-ha examples/ha-contract.json --ha-states examples/ha-states.synthetic.json > /tmp/meter-contract.json
ha-meter-contracts check /tmp/meter-contract.json --at 2026-01-01T12:00:05Z --json --lang ru
```

Укажите `entity_id` и `timestamp_attribute` для каждого импортируемого измерителя. Экспорт — массив объектов HA с `entity_id`, `state`, `attributes`. Указанный атрибут должен содержать исходное время измерения ISO с часовым поясом. `attributes.unit_of_measurement` должен соответствовать физической величине; W/kW и Wh/kWh автоматически переводятся в единицы контракта.

Копируются только сопоставленные значения и исходное время; прочие атрибуты, включая friendly name, игнорируются. При строго более новом измерении имеющийся `sample` становится `previous`. Повтор одинакового значения с той же исходной меткой времени ничего не меняет. Более старое измерение или другое значение с той же меткой отклоняется с кодом `ha_sample_order`. Отсутствующая сущность, `unknown` и `unavailable` очищают sample, но не становятся нулём. Отсутствующее время, несовместимая единица, неправильное число или повторный entity ID завершают импорт кодом 2. Несопоставленные измерители не меняются.

Обычный экспорт HA часто не содержит исходной метки устройства. В этом случае адаптер не выдумывает её: нужен источник с временем или unavailable. `last_changed`, `last_updated`, `last_reported` не доказывают время физического измерения. Адаптер не обращается к `/api/states`, не использует токен и не копирует сбросы счётчика из HA: подтверждённый `reset_at` для энергии укажите отдельно.

## Порядок внедрения

1. По реальной схеме объявите области и происхождение потоков.
2. Проверьте один измеритель на синтетическом примере.
3. Сохраните необходимые реальные наблюдения в приватный файл.
4. Разберите отчёт до изменения автоматизации.
5. При миграции сохраняйте исходное время и данные калибровки.

Программа не переименовывает сущности, не сбрасывает устройства и не разворачивает автоматизации.
