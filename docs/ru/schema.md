Машиночитаемый [schema.json](../../schema.json) описывает структуру. Парсер Python определяет точные ограничения; `audit` добавляет физическую и временную семантику, которую JSON Schema доказать не может. Структурный файл создаётся командой `python3 scripts/generate_schema.py`.

<a id="root-and-limits"></a>

## Корень и ограничения

Обязательны целое `schema_version: 1`, `scopes`, `meters`. Необязателен `sums` (по умолчанию пуст). Неизвестные поля отклоняются на каждом уровне контракта. Максимум 512 областей, 512 измерителей и 128 сумм; области и измерители не должны быть пустыми. В каждой сумме 1–512 участников. Ввод — UTF-8, до 1 048 576 байт, глубина вложения 16, до 20 000 узлов значений. Повторные ключи JSON, NaN/Infinity, псевдонимы/якоря/явные теги YAML запрещены. Заключайте временные метки YAML в кавычки, чтобы они оставались строками.

Идентификаторы содержат 1–96 ASCII-символов: сначала буква/цифра, затем буквы, цифры, `.`, `_`, `-`. ID уникальны внутри коллекции; пространства имён областей и измерителей независимы. Время содержит `T` и часовой пояс. Числа конечны, не являются булевыми и лежат в пределах ±10^15, если не указан более узкий диапазон.

<a id="physical-scopes"></a>

## Физические области

У каждой области есть `id`, `kind` (`site`, `circuit`, `strip`, `outlet`, `load`) и необязательный `parent`. Родители должны существовать и образовывать лес без циклов. Измеритель на родительской области покрывает всех её потомков. Типы областей описательны: они не выводят напряжение, фазы, номиналы, проводку или допустимых родителей. Настоящую топологию объявляете вы.

<a id="meters"></a>

## Измерители

Обязательные поля:

- `id`, `scope`: уникальный идентификатор измерения и объявленная физическая область.
- `quantity`: `power`, `energy`, `voltage`, `current`.
- `unit`: соответственно W/kW, Wh/kWh, V, A. Парсер принимает словарь, аудитор проверяет размерность.
- `kind`: `measured` или `estimated`. Это объявление, а не лабораторная проверка.
- `provenance`: постоянная идентичность физического потока измерений, **не** его представления в HA/MQTT. Псевдонимы используют её совместно. Различные знак/величина/область при одном происхождении означают конфликт; каждый псевдоним конфликтующего потока становится недоступным для сумм независимо от порядка ввода. Для действительно разных направленных потоков выбирайте отдельное происхождение.
- `sign`: `nonnegative` для величины только потребления/импорта/экспорта; `signed` для объявленного двунаправленного потока. Этот выпуск не определяет, какое физическое направление положительно.
- `state_class`: `measurement`, `total`, `total_increasing`.
- `freshness_seconds`: положительный допустимый возраст, 0.001–604800 секунд.

Необязательный `reset`: `never`, `periodic`, `device_restart`, `unknown`, `not_applicable` (по умолчанию). Для энергии нужна явная политика, отличная от `not_applicable`, и класс состояния типа total. Знаковая энергия несовместима с `total_increasing`. Другие величины требуют `measurement` и `not_applicable`.

Необязательные `sample`, `previous`: null или объект с `value` (число или null), `measured_at` и необязательным `reset_at`. Предыдущий отсчёт должен быть старше. Уменьшение неотрицательного счётчика требует метки сброса между отсчётами; `never` его отклоняет. `reset_at` не должен быть позже своего отсчёта и применим только к энергии. Неизвестная семантика сброса даёт предупреждение. Знаковый нетто-счётчик может законно уменьшаться; правильная базовая точка остаётся ответственностью производителя данных.

Необязательная `calibration`: `quantity`, положительный `factor` (10^-12–10^12), синтетический/приватный идентификатор `reference`, `verified_at`. Это свидетельство ровно для указанной величины. Значения отсчётов **уже откалиброваны**: валидатор не применяет коэффициент повторно. Калибровка из будущего или калибровка напряжения у измерителя мощности недопустима. Отсутствие калибровки не доказывает точность и не является автоматической ошибкой.

Необязательные `entity_id`, `timestamp_attribute`: офлайн-сопоставление HA; см. [использование](usage.md#offline-home-assistant-adapter).

<a id="sums"></a>

## Суммы

Обязательны `id`, целевая `scope`, список ID измерителей в `meters`, `quantity` (`power` или `energy`), `coverage` (`partial` или `complete`). Необязательный `max_skew_seconds`: 0–604800, по умолчанию 2.

Участники должны находиться внутри целевой области, иметь совместимые размерности и семантику знака, использовать разные физические потоки и не перекрываться как родитель/потомок или одинаковые области. Полная сумма должна покрывать каждый **объявленный лист дерева** под целевой областью. Необъявленную проводку обнаружить невозможно. Частичная сумма явно сообщает частичное покрытие. Вложенные суммы не поддерживаются; участники всегда ссылаются на измерители.

У каждого участника должны быть корректные свежие данные; время получения должно укладываться в допустимый разброс. Для энергии дополнительно требуются одинаковые явные начала `reset_at`. Проверяется объявленная согласованность, а не точность исторического накопления счётчиков. Суммы переводятся в W или Wh. Суммы тока и напряжения намеренно не поддерживаются: их смысл зависит от топологии цепи.

Числовая сумма недоступна, если отсутствует обязательное свидетельство или не прошла семантическая проверка. Оценки распространяются как `kind: estimated`. Два псевдонима могут сосуществовать в инвентаре, но не могут оба участвовать в сумме. Итог для неизмеренных отдельных розеток не выводится.

<a id="report-v1"></a>

## Отчёт v1

Корень: `schema_version`, время оценки `at` в UTC, счётчики серьёзности в `summary`, отсортированные `findings` и `sums`. Каждая находка содержит `code`, `severity`, JSON-путь `path`, структурированные `params`; CLI добавляет `message`. Каждая сумма содержит `id`, `scope`, `quantity`, базовую `unit`, `value`, `status`, `kind`, `coverage`. Неизвестные значения — JSON null, никогда не NaN.
