# Схема контракта v1

[Машиночитаемый schema.json](../../schema.json) проверяет структуру. Парсер Python задаёт точные ограничения, а `audit` дополнительно проверяет физические связи и время. Генератор: `python3 scripts/generate_schema.py`.

## Корень и пределы

Обязательны целое `schema_version: 1`, `scopes`, `meters`; `sums` необязателен, по умолчанию пуст. Неизвестные поля запрещены на каждом уровне. Максимум 512 областей, 512 измерителей, 128 сумм; первые две коллекции непустые. В сумме 1–512 участников. UTF-8, не более 1 048 576 байт, глубина до 16, до 20 000 узлов значений. Повторные ключи, NaN/Infinity, YAML-якоря, ссылки и явные теги запрещены. Даты в YAML заключайте в кавычки.

ID: 1–96 ASCII-символов, первый — буква или цифра, далее также `.`, `_`, `-`. Внутри коллекции ID уникальны; пространства ID областей и измерителей независимы. Метка времени содержит `T` и часовой пояс. Число конечное, не boolean, в пределах ±10^15, если для поля не задан более узкий диапазон.

## Физические области

У области есть `id`, `kind` (`site`, `circuit`, `strip`, `outlet`, `load`) и необязательный `parent`. Родитель должен существовать; циклы запрещены. Измерение родительской области включает её потомков. `kind` описательный: он не выводит напряжение, фазы, допустимый ток или реальные соединения. Достоверность дерева обеспечивает оператор.

## Измерители

Обязательные поля:

- `id`, `scope`: идентификатор измерения и его физическая область.
- `quantity`: `power`, `energy`, `voltage`, `current`.
- `unit`: соответственно W/kW, Wh/kWh, V, A. Парсер проверяет словарь, аудитор — соответствие величине.
- `kind`: `measured` или `estimated`; это заявление, а не лабораторная приёмка.
- `provenance`: постоянный ID физического потока, а не копии в MQTT/HA. Псевдонимы имеют одинаковый provenance. Несовместимые scope/quantity/sign одного происхождения — ошибка: все псевдонимы этого потока исключаются из сумм независимо от порядка входных записей. Для действительно разных направленных потоков нужны разные ID.
- `sign`: `nonnegative` для неотрицательной величины потребления/импорта/экспорта; `signed` для двунаправленного потока. Положительное физическое направление программа не угадывает.
- `state_class`: `measurement`, `total`, `total_increasing`.
- `freshness_seconds`: от 0.001 до 604800 секунд.

Необязательный `reset`: `never`, `periodic`, `device_restart`, `unknown`, `not_applicable` (по умолчанию). Для энергии нужна явная применимая политика и класс total. Signed-энергия несовместима с `total_increasing`. Остальные величины требуют `measurement` и `not_applicable`.

`sample`, `previous`: null или объект с `value` (число/null), `measured_at`, необязательным `reset_at`. Previous должен быть старше. Уменьшение неотрицательного счётчика требует метки сброса между отсчётами; при `never` оно ошибочно. Reset не позже измерения и применим только к энергии. Неизвестная политика даёт предупреждение. Signed net energy может законно уменьшаться; корректность её базовой точки остаётся ответственностью источника.

`calibration`: `quantity`, положительный `factor` от 10^-12 до 10^12, ID эталона `reference`, время `verified_at`. Это свидетельство только для указанной величины. Значения sample уже должны быть откалиброваны: коэффициент повторно **не применяется**. Калибровка из будущего или калибровка вольт для ватт — ошибка. Отсутствие записи само по себе не ошибка, но и не доказательство точности.

`entity_id`, `timestamp_attribute` задают необязательный офлайн-импорт HA; см. [использование](usage.md).

## Суммы

Обязательны `id`, целевая `scope`, список ID `meters`, `quantity` (`power` или `energy`) и `coverage` (`partial`, `complete`). `max_skew_seconds` необязателен: 0–604800, по умолчанию 2 секунды.

Каждый участник должен находиться внутри целевой области. Величины и семантика знака совпадают, физические потоки независимы, области не перекрываются. Родитель и ребёнок в одной сумме запрещены. `complete` требует покрытия каждого **объявленного конечного потомка**; неизвестную проводку проверить невозможно. `partial` сохраняется в отчёте. Вложенных сумм нет: участник всегда измеритель.

Все отсчёты должны быть пригодны и свежи, а их время — согласовано в пределах skew. Для энергии нужен одинаковый явный `reset_at`, обозначающий начало накопления. Это проверка объявления, не достоверности всей истории. Результат в W или Wh. Суммы тока/напряжения не поддерживаются, поскольку зависят от электрической схемы.

При ошибке или недостатке данных value становится null. Наличие оценки даёт `kind: estimated`. Псевдонимы могут сосуществовать в инвентаре, но не складываться. Индивидуальная мощность неизмеряемых выходов не выводится.

## Отчёт v1

Поля корня: `schema_version`, `at` в UTC, счётчики `summary`, отсортированные `findings`, результаты `sums`. Находка: `code`, `severity`, путь `path`, параметры `params`; CLI добавляет `message`. Сумма: `id`, `scope`, `quantity`, базовая `unit`, `value`, `status`, `kind`, `coverage`. Неизвестное значение — JSON null, не NaN.
