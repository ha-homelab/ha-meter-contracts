<a id="root-and-limits"></a>

## ระดับรากและขีดจำกัด

ต้องมีจำนวนเต็ม `schema_version: 1`, `scopes`, `meters` ส่วน `sums` เป็นทางเลือกและเริ่มต้นว่าง ฟิลด์ไม่รู้จักถูกปฏิเสธทุกระดับ สูงสุด 512 ขอบเขต 512 มิเตอร์ และ 128 ผลรวม ขอบเขตและมิเตอร์ต้องไม่ว่าง แต่ละผลรวมมีสมาชิก 1–512 รายการ อินพุต UTF-8 สูงสุด 1,048,576 ไบต์ ความลึก 16 และโหนดค่า 20,000 โหนด ปฏิเสธคีย์ JSON ซ้ำ NaN/Infinity และ alias/anchor/tag ที่ระบุชัดใน YAML ใส่เวลา YAML ในเครื่องหมายคำพูดเพื่อคงเป็นสตริง

ตัวระบุมีอักขระ ASCII 1–96 ตัว เริ่มด้วยตัวอักษร/ตัวเลข จากนั้นเป็นตัวอักษร ตัวเลข `.`, `_`, `-` ID ต้องไม่ซ้ำในแต่ละคอลเลกชัน ขอบเขตและมิเตอร์มีเนมสเปซแยกกัน เวลาทั้งหมดมี `T` และเขตเวลา ตัวเลขต้องมีค่าจำกัด ไม่ใช่บูลีน และอยู่ใน ±10^15 เว้นแต่มีขีดจำกัดเข้มกว่า

<a id="physical-scopes"></a>

## ขอบเขตทางกายภาพ

แต่ละขอบเขตมี `id`, `kind` (`site`, `circuit`, `strip`, `outlet`, `load`) และอาจมี `parent` โหนดแม่ต้องมีอยู่และสร้างป่าแบบไร้วงจร มิเตอร์บนโหนดแม่ครอบคลุมลูกหลานทั้งหมด ประเภทขอบเขตใช้บรรยาย ไม่อนุมานแรงดัน เฟส พิกัด การเดินสาย หรือโหนดแม่ที่อนุญาต ผู้ใช้เป็นผู้ประกาศโทโพโลยีจริง

<a id="meters"></a>

## มิเตอร์

ฟิลด์ที่ต้องมี:

- `id`, `scope`: ตัวระบุค่าการอ่านที่ไม่ซ้ำและขอบเขตกายภาพที่ประกาศ
- `quantity`: `power`, `energy`, `voltage`, `current`
- `unit`: W/kW, Wh/kWh, V, A ตามลำดับ ตัวแยกวิเคราะห์ยอมรับคำศัพท์ ตัวตรวจสอบตรวจมิติ
- `kind`: `measured` หรือ `estimated` เป็นคำประกาศ ไม่ใช่การตรวจสอบในห้องปฏิบัติการ
- `provenance`: อัตลักษณ์คงที่ของกระแสการวัดจริง **ไม่ใช่**รูปแทน HA/MQTT ค่าการอ่านที่เป็นชื่อแทนใช้อัตลักษณ์เดียวกัน เครื่องหมาย/ปริมาณ/ขอบเขตต่างกันภายใต้แหล่งกำเนิดเดียวเป็นความขัดแย้ง ชื่อแทนทั้งหมดของกระแสนั้นจะใช้รวมไม่ได้โดยไม่ขึ้นกับลำดับอินพุต ใช้แหล่งกำเนิดแยกกันสำหรับช่องทางกายภาพที่ต่างกันจริง
- `sign`: `nonnegative` สำหรับขนาดของการใช้/นำเข้า/ส่งออกอย่างเดียว และ `signed` สำหรับการไหลสองทิศทางที่ประกาศ รุ่นนี้ไม่อนุมานว่าทิศทางกายภาพใดเป็นบวก
- `state_class`: `measurement`, `total`, `total_increasing`
- `freshness_seconds`: อายุสูงสุดที่เป็นบวก 0.001–604800 วินาที

`reset` เป็นทางเลือก: `never`, `periodic`, `device_restart`, `unknown`, `not_applicable` (ค่าเริ่มต้น) พลังงานต้องมีนโยบายชัดเจนที่ไม่ใช่ `not_applicable` และคลาสสถานะแบบ total พลังงานมีเครื่องหมายใช้ `total_increasing` ไม่ได้ ปริมาณอื่นต้องเป็น `measurement` และ `not_applicable`

`sample`, `previous` เป็นทางเลือก: null หรือออบเจ็กต์ที่มี `value` (ตัวเลขหรือ null), `measured_at` และอาจมี `reset_at` ตัวอย่างก่อนหน้าต้องเก่ากว่า การลดลงของตัวนับไม่ติดลบต้องมีเครื่องหมายรีเซ็ตระหว่างตัวอย่าง โดย `never` จะปฏิเสธมัน `reset_at` ต้องไม่หลังเวลาตัวอย่างของตนและใช้กับพลังงานเท่านั้น ความหมายรีเซ็ตที่ไม่ทราบทำให้เกิดคำเตือน ตัวนับสุทธิที่มีเครื่องหมายลดลงได้อย่างถูกต้อง แต่จุดฐานที่ถูกต้องยังเป็นหน้าที่ของผู้ผลิตข้อมูล

`calibration` เป็นทางเลือก: `quantity`, `factor` บวก (10^-12–10^12), ตัวระบุสังเคราะห์/ส่วนตัว `reference`, `verified_at` ใช้บันทึกหลักฐานสำหรับปริมาณนั้นโดยเฉพาะ ค่า**ผ่านการสอบเทียบแล้ว** ตัวตรวจสอบไม่คูณซ้ำ การสอบเทียบในอนาคตหรือการสอบเทียบแรงดันกับมิเตอร์กำลังไม่ถูกต้อง การไม่มีข้อมูลสอบเทียบไม่พิสูจน์ความแม่นยำและไม่เป็นข้อผิดพลาดโดยอัตโนมัติ

`entity_id`, `timestamp_attribute` เป็นทางเลือกสำหรับการแมป HA แบบออฟไลน์ ดู[การใช้งาน](usage.md#offline-home-assistant-adapter)

<a id="sums"></a>

## ผลรวม

ต้องมี `id`, `scope` เป้าหมาย, รายการ ID มิเตอร์ใน `meters`, `quantity` (`power` หรือ `energy`), `coverage` (`partial` หรือ `complete`) ส่วน `max_skew_seconds` เป็นทางเลือก: 0–604800 ค่าเริ่มต้น 2

สมาชิกต้องอยู่ในขอบเขตเป้าหมาย มีมิติและความหมายเครื่องหมายที่เข้ากัน ใช้กระแสกายภาพต่างกัน และไม่ทับซ้อนในรูปแม่/ลูกหรือขอบเขตเดียวกัน ผลรวมครบถ้วนต้องครอบคลุมทุก**ขอบเขตใบที่ประกาศ**ใต้เป้าหมาย ไม่สามารถค้นพบการเดินสายที่ไม่ได้ประกาศ ผลรวมบางส่วนประกาศการครอบคลุมบางส่วนอย่างชัดเจน ไม่รองรับผลรวมซ้อนกัน สมาชิกต้องอ้างถึงมิเตอร์เสมอ

ทุกสมาชิกต้องมีข้อมูลถูกต้องและสดใหม่ เวลาเก็บข้อมูลต้องอยู่ในความคลาดเคลื่อนที่อนุญาต พลังงานยังต้องมีจุดเริ่มต้น `reset_at` ที่ระบุชัดและเหมือนกัน นี่ตรวจความสอดคล้องที่ประกาศ ไม่ใช่ความแม่นยำของการสะสมย้อนหลัง ผลรวมแปลงเป็น W หรือ Wh จงใจไม่รองรับผลรวมกระแสและแรงดันเนื่องจากขึ้นกับโทโพโลยีวงจร

ผลรวมตัวเลขจะไม่พร้อมใช้หากขาดหลักฐานจำเป็นหรือไม่ผ่านการตรวจความหมาย ค่าประมาณส่งต่อเป็น `kind: estimated` ชื่อแทนสองชื่ออยู่ร่วมในทะเบียนได้ แต่ร่วมกันเป็นสมาชิกผลรวมเดียวไม่ได้ ไม่อนุมานผลรวมสำหรับเต้ารับรายตัวที่ไม่มีการวัด

<a id="report-v1"></a>

## รายงาน v1

ระดับราก: `schema_version`, เวลาประเมิน `at` ที่ปรับเป็น UTC, จำนวนตามความรุนแรงใน `summary`, `findings` ที่เรียงแล้ว และ `sums` แต่ละข้อค้นพบมี `code`, `severity`, `path` แบบ JSON, `params` ที่มีโครงสร้าง CLI เพิ่ม `message` แต่ละผลรวมมี `id`, `scope`, `quantity`, `unit` ฐาน, `value`, `status`, `kind`, `coverage` ค่าที่ไม่ทราบเป็น JSON null ไม่ใช่ NaN
