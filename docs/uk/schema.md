Машиночитана [schema.json](../../schema.json) описує структуру. Парсер Python є визначальним щодо обмежень; `audit` додає фізичну й часову семантику, яку JSON Schema не може довести. Створюйте структурний файл командою `python3 scripts/generate_schema.py`.

<a id="root-and-limits"></a>

## Корінь та обмеження

Обов’язкові: ціле `schema_version: 1`, `scopes`, `meters`. Необов’язкове: `sums` (типово порожнє). Невідомі поля відхиляються на кожному рівні. Максимум 512 областей, 512 вимірювачів і 128 сум; області й вимірювачі не можуть бути порожніми. Кожна сума має 1–512 членів. Введення UTF-8, максимум 1 048 576 байтів, глибина 16 та 20 000 вузлів значень. Дублікати ключів JSON, NaN/Infinity та псевдоніми/якорі/явні теги YAML відхиляються. Беріть часові позначки YAML у лапки, щоб вони залишалися рядками.

Ідентифікатори містять 1–96 символів ASCII: спочатку літера/цифра, потім літери, цифри, `.`, `_`, `-`. ID унікальні в межах кожної колекції; області й вимірювачі мають окремі простори імен. Усі часові позначки містять `T` і часовий пояс. Числа скінченні, не булеві, у межах ±10^15, якщо немає суворішого обмеження.

<a id="physical-scopes"></a>

## Фізичні області

Кожна область має `id`, `kind` (`site`, `circuit`, `strip`, `outlet`, `load`) і необов’язкове `parent`. Батьківські області мають існувати й утворювати ациклічний ліс. Вимірювач на батьківській області охоплює всіх нащадків. Типи областей описові: вони не визначають напругу, фази, номінали, проводку чи дозволених батьків. Справжню топологію декларує користувач.

<a id="meters"></a>

## Вимірювачі

Обов’язкові поля:

- `id`, `scope`: унікальний ідентифікатор показника та задекларована фізична область.
- `quantity`: `power`, `energy`, `voltage`, `current`.
- `unit`: відповідно W/kW, Wh/kWh, V, A. Парсер приймає словник; аудитор перевіряє розмірність.
- `kind`: `measured` або `estimated`. Це декларація, а не лабораторна перевірка.
- `provenance`: стала ідентичність фізичного потоку вимірювань, **не** його представлення HA/MQTT. Показники-псевдоніми поділяють її. Різні знаки/величини/області з одним походженням створюють конфлікт; усі псевдоніми потоку стають недоступними для сум незалежно від порядку введення. Для справді різних фізичних каналів вибирайте різне походження.
- `sign`: `nonnegative` для величин лише споживання/імпорту/експорту; `signed` для задекларованого двонапрямного потоку. Ця версія не виводить, який фізичний напрямок додатний.
- `state_class`: `measurement`, `total`, `total_increasing`.
- `freshness_seconds`: додатний максимальний вік, 0.001–604800 секунд.

Необов’язкове `reset`: `never`, `periodic`, `device_restart`, `unknown`, `not_applicable` (типове). Енергія потребує явної політики, відмінної від `not_applicable`, і класу стану типу total. Енергія зі знаком не може використовувати `total_increasing`. Інші величини потребують `measurement` та `not_applicable`.

Необов’язкові `sample`, `previous`: null або об’єкт із `value` (число чи null), `measured_at`, необов’язковим `reset_at`. Попередній відлік має бути старішим. Зменшення невід’ємного лічильника потребує позначки скидання між відліками; `never` її відхиляє. `reset_at` не може бути пізнішим за свій відлік і застосовується лише до енергії. Невідома семантика скидання породжує попередження. Чистий лічильник зі знаком може правомірно зменшуватися; правильна база залишається відповідальністю виробника.

Необов’язкове `calibration`: `quantity`, додатний `factor` (10^-12–10^12), синтетичний/приватний ідентифікатор `reference`, `verified_at`. Записує свідчення саме для цієї величини. Значення **вже відкалібровані**: валідатор ніколи не застосовує коефіцієнт повторно. Калібрування з майбутнього або калібрування напруги на вимірювачі потужності некоректне. Відсутність калібрування не доводить точності й не є автоматично помилкою.

Необов’язкові `entity_id`, `timestamp_attribute`: автономне зіставлення HA; див. [використання](usage.md#offline-home-assistant-adapter).

<a id="sums"></a>

## Суми

Обов’язкові: `id`, цільова `scope`, список ID вимірювачів у `meters`, `quantity` (`power` або `energy`), `coverage` (`partial` або `complete`). Необов’язкове `max_skew_seconds`: 0–604800, типово 2.

Члени мають належати до цільової області, мати сумісні розмірності й семантику знака, використовувати різні фізичні потоки та не перекриватися як батько/нащадок чи однакові області. Повна сума охоплює кожну **задекларовану листкову область** під ціллю. Незадекларовану проводку неможливо виявити. Часткова сума явно декларує часткове покриття. Вкладені суми не підтримуються; члени завжди посилаються на вимірювачі.

Кожен член повинен мати коректні свіжі дані; час отримання має вкладатися в дозволене відхилення. Енергія також потребує однакових явних початків `reset_at`. Перевіряється задеклароване узгодження, а не точність історичного накопичення. Суми перетворюються на W або Wh. Суми струму й напруги навмисно не підтримуються, оскільки залежать від топології кола.

Числова сума недоступна, якщо бракує потрібних свідчень або не проходить семантична перевірка. Оцінки поширюються як `kind: estimated`. Два псевдоніми можуть співіснувати в інвентарі, але не можуть обидва входити до суми. Жодного підсумку для окремих невиміряних розеток не виводиться.

<a id="report-v1"></a>

## Звіт v1

Корінь: `schema_version`, час оцінювання `at`, нормалізований до UTC, кількість за серйозністю в `summary`, упорядковані `findings` і `sums`. Кожна знахідка містить `code`, `severity`, `path` у стилі JSON, структуровані `params`; CLI додає `message`. Кожна сума містить `id`, `scope`, `quantity`, базову `unit`, `value`, `status`, `kind`, `coverage`. Невідомі значення — JSON null, ніколи NaN.
